This checkpoint follows `818cae8` and includes the recent magnification, cursor, capture and wake work. Use [XR regression requirements](xr-regression-requirements.md) as the current behavior contract. The older [refactor review](refactor-review-2026-11-16.md) and reliability notes trace earlier decisions, including features that have since changed. ## What shipped in this checkpoint

- **Magnification.** Saved magnifiers support Gaze to magnify and Aim to magnify with dwell and explicit pinning. A hand resting on the current magnifier leaves desktop gaze free to select a different window. The desktop detail patch shares window capture. X11 companion windows use the owner's capture atlas and become individually placed, targetable regions. Explicit transient ownership takes precedence. Thunderbird Compose also groups by its Compose role and matching client leader when there is one main mail window. Independent top-level windows stay separate. Existing X11 menu heuristics are scoped to menu-like windows.
- **Curved panes.** Fixed magnifiers retain a spherical canvas and adapt its image aperture to the source aspect ratio. Curved child windows now also retain a canvas and update the visible rectangle and collision geometry together. A larger child can require a larger canvas. The user reports that the latest child-window fix appears to work. Long-running stress across multiple child windows, menu cascades and projection changes remains open.
- **Connected cursor.** Hand Mouse takes root pixels from the captured source region. The host topology owns the real cursor's logical space. The headset draws a separate, soft cyan marker on that owner's sightline, with a depth allowance for video ordering and constant apparent size. The user accepted the current marker. The host still supplies mirrored cursor imagery in capture, with atlas cursor paint assigned to the appropriate source region.
- **Wake and presentation.** On wake, reacquire Full Space and tracking, preserve attached native scene objects, and recover video outputs and keyframes. Remount only if the scene root is detached. An ADB sleep/wake test observed the same process recover tracking and present desktop, magnifier and panel frames. Extended standby and wearer-visible recovery still need repeated testing. The host sends one paced follow-up frame after isolated changes so terminal edits and paste actions can leave the decoder queue even when the desktop becomes static.
- **Controls.** Built-in palm and layout menus group related actions and preserve user edits. Workspace retains per-screen controls and layout editing. Check these alongside input routing when changing menus or operation modes.

## Ownership and change rules

| Area | Starting points | Contract to preserve |
| --- | --- | --- |
| Authored workspace and pose | `workspace/Workspace.kt`, `workspace/WorkspacePlacement.kt`, layout history and adjustment helpers | Persist authored placement. Focus, wake, head tracking and aperture fit produce derived poses. Persist only explicit layout edits. Preserve the reference coordinate system and valid preferences when recovering bad tracking. |
| Submitted XR geometry | `MonitorMesh.kt`, `MonitorWarp.kt`, `DesktopScene.kt`, `WindowMagnification.kt`, `WindowMagnifierPanel.kt` | Use the same geometry path at startup, after a mode switch and when a source changes. Publish only geometry the surface submitted. Use it for visible bounds, hit testing, cursor placement, overlay depth and desktop cutouts. Use stable spherical projection everywhere the flat/curved setting applies. |
| Native resource lifetime | `NativeSurfaceResources.kt`, `NativeNodeState.kt`, `CurvedMonitorInput.kt`, `DeskConnection.tryNativeMeshUpdate` | Keep video canvas, collider and producer lifetimes explicit. Hide and reuse surfaces across ordinary visibility and source changes. Update transforms and aperture parameters without replacing materials. Gate allocations and mutations, keep upload buffers bounded, and detach video producers and input before retiring geometry. |
| Hand and gaze interaction | `PointerControl.kt`, `MouseGestures.kt`, `MagnifierContacts.kt`, `GrabInteraction.kt`, `WorkspaceRuntime.kt` | Resolve the owner and contact before interpreting gestures. Share pinch thresholds and edge semantics. Preserve a captured drag owner through hover loss and release the host button on cancellation or pause. Keep hand aim, gaze magnification, desktop-reference focus, and layout arbitration explicit. |
| Cursor topology | `CursorTopology.kt`, `DeskConnection.kt`, `crates/host/src/session/cursor_map.rs` | Keep the authored axis-aligned map, host root pixels, source UVs and scene poses distinct. Front overlap wins. Cross aligned gaps along one axis and clamp blocked edges. A host warp or content swap must not steal ownership from a retained pane. |
| Streams and windows | `net/DeskConnection.kt`, `net/WindowCapturePool.kt`, `media/VideoCompositor.kt`, host `session/streaming.rs`, `session/window.rs` and `platform/x11/windows.rs` | Keep owner and child crops synchronized with decoded frame metadata. Share capture and decoding. Use cropped visible content and measured frame pacing. Keep the terminal follow-up frame, monitor layout notifications, low refresh rates and X11 input-device safeguards. |

Use explicit ownership keys at boundaries. A stable layout slot, a changing X11 window ID, a captured region, and a native surface generation have different lifetimes. Route paint, input and readiness through the same submitted pane or frame generation. Keep pure mapping and arbitration testable. Centralize shared policy before adding a per-mode path. Keep persisted fields and protocol metadata backward compatible. The saved `gaze_to_focus` key currently backs the Gaze to magnify control, and `aim_to_magnify` is a separate setting.

The [crash-route inventory](xr-crash-routes.md) records confirmed failures, device evidence, and reported routes still requiring reproduction. Native rendering has two recurring crash signatures. The SplitEngine worker has aborted on an unknown material instance during child and ordinary scene transitions. Other crashes faulted in the native custom-mesh setter. A child once triggered the abort shortly after its first presented frame, and the same native abort also occurred outside that reproduction. A build passing or a pane reporting ready is insufficient evidence of a universal fix. For each recurrence, record the device timestamp, process ID, mode, owner/child ID, native surface generation and the immediately preceding create/resize/show/hide sequence. Use device crash logs and a bounded, targeted trace. Avoid recurring capture dumps.

## Priorities for the architect

1. Make submitted surface state an explicit shared contract. Consolidate the publication of geometry, visible aperture, source mapping, owner and readiness. Remove fallback paths that silently substitute authored or provisional geometry for visible geometry.
2. Reduce the responsibilities of `WorkspaceRuntime.kt` and `WindowMagnifierPanel.kt` in small, behavior-preserving changes. Extract input arbitration, pane resource ownership and wake coordination behind testable interfaces. Measure before proposing engine or language changes. Native scene operations, frame cadence and thermal load are the evidence to follow.
3. Establish a repeatable headset matrix. Cover cold start, sleep/wake, host reconnect, Workspace close, flat-to-curved-to-flat, enlarged desktop overlaps, Mountlet child open/resize/close, and nested menus. Test single- and two-hand routing, drag capture and release, cursor ownership through overlap, gaze switching while a hand aims at the magnifier, and palm edits. Verify the actual view and hit area. For timing, compare presented frames, native allocations, CPU, memory and thermal state through a sustained run.
4. Review relevant regression requirements with every feature. Add a focused test for a recurring failure and put headset-only checks in the validation plan. Run `python3 scripts/verify.py` for host and JVM checks, `--group android` for Android build and lint, and the applicable device/integration checks. Report which checks ran and which outcomes still depend on headset observation.

The highest-risk change is replacing a video surface or material while its producer, collider or the XR renderer can still reference it. Treat that as a transaction with a documented owner and lifetime. Keep the accepted visual behavior, input behavior and stream quality as part of the same change.
