# Floatdesk crash routes

This is the architect's triage inventory. Device-log timestamps below are recorded as shown by the headset. A scenario reported by the user is a reproduction lead. It becomes a confirmed route only when the log identifies the failing process, thread and operation.

## Confirmed failures

| Failure | Observed route | Current mitigation and open work |
| --- | --- | --- |
| SplitEngine `NOT_FOUND`, unknown material instance, SIGABRT on `imp_bg_wk` | Spawn or resize a curved companion pane. The latest captured Mountlet sequence showed a replacement in the owner's child slot, reuse of that child, a new thin descendant presenting at **00:18:23.030 on Nov 27**, and the abort **49 ms later**. Earlier traces showed the same pattern after Mountlet child presentation and after a capture disconnect. The abort alone does not identify which surface owned the missing material. | Retain child slots and spherical canvases, coalesce metadata, keep atlas codecs stable and match crops to the presented frame. Use default backing dimensions for new child surfaces to avoid an immediate texture resize. Let the child present before updating desktop cutout geometry. Keep a separate collider only where the shape needs it. Live Mountlet stress remains open. |
| Same SplitEngine abort during initialization or scene transition | Cold launch and wake have both failed with this signature. Fresh launches on Nov 26 at 23:34 and Nov 27 at 00:09 produced material aborts. Some other launches recovered immediately and resumed video. | Preserve attached objects across wake, wait for spatial capabilities, retry root discovery and pace native surface creation. Keep the cold-start and wake tests independent of Mountlet. |
| SplitEngine duplicate material (`ALREADY_EXISTS`) and texture borrower assertions | Older navigation traces showed duplicate material IDs and a backing texture being released while a model creator still borrowed it. | Retain shared collider models per session, detach dependents and stop video producers before retiring materials. Verify cancelled loads, mode swaps and close/reopen sequences. |
| Filament command-buffer overflow | An earlier device trace overflowed the backend command buffer while creating a magnifier stereo surface. | Reduce repeated native surface creation and bound mesh upload size. Capture native queue timings if it recurs. |
| Native custom-mesh setter SIGSEGV | Stack traces reach `nSetStereoSurfaceEntityCanvasShapeCustomMesh` through `MonitorWarp.applyShape` and the desktop compositor's shape gate. | Validate arrays and use independent triangles, retain upload buffers, coalesce shape changes and serialize them with active output drawing. Keep this separate from startup material aborts. |
| Native final teardown SIGSEGV | An earlier teardown trace faults in `nDisposeAllResources`. | Stop producers and release app-owned dependents while SceneCore is alive. Back moves the task to the background. Test real Activity finish separately from Home and normal sleep. |
| Java crash on detached XR parent | Wake/rebuild traces showed `Cannot get scale in ActivitySpace with a null parent` in workspace tracking. | Validate coordinate transforms and skip the affected frame while parenting catches up. Ordinary wake preserves the scene. |
| Auto adjust geometry exception | Two Nov 27 device traces stop in the `MonitorMesh` focus requirement when the layout solver builds a desktop footprint. | Layout and presentation share one spherical desktop builder with two explicit focus coordinates. Reject invalid geometry without publishing a partial adjustment. Replay the installed APK against representative saved layouts. |
| HUD bitmap reuse crash | Late Compose/RenderThread drawing tried to draw a recycled bitmap after diagnostics removal. | The HUD closes its draw path before bitmap reclamation. Repeat diagnostics open/close during active streaming. |
| Startup/screen-off ANR | Main thread blocked in `setExternalTextureSurfaceSize` called from the initial desktop surface callback. | Size the backing surface in the resumed frame loop. Keep this distinct from SIGABRT and decoder recovery. |
| Host Plasma session crash on Floatdesk shutdown | Removing the extra Floatdesk Hover XInput master keyboard/pointer pair coincided with simultaneous Qt XCB crashes, including KWin and the session manager. | Aim to hover must never create or remove an XInput master pair. Verify host shutdown from a private X session when changing input lifetime. |

## Reported routes to keep in the device matrix

- Open and close Workspace, especially while a curved pane is visible. Enter Layout with guides and resize handles active. Toggle diagnostics during active streaming.
- Switch flat to spherical and back while magnifying. Add, remove or re-enable a magnifier or desktop reference. Switch between portrait and landscape sources and open a child while the owner capture is restarting.
- Open a taskbar preview, system launcher or context menu. Rapidly change hovered icons, swap single/multiple-window previews, and open nested menus from a magnified Mountlet child. Exercise input, rapid redraws and closing the popup from the headset and host.
- Test long standby, normal wake, activity finish and force-stop/relaunch separately. A gray scene after wake is a recovery failure even when the process remains alive. Recovered video frames do not prove valid native input.
- Severe or critical thermal load has correlated with system-wide stutter and some reported crashes. Thermal state, stream FPS and memory do not identify the crashing operation. Host GPU hangs and subsequent loss of connection are separate incidents. Earlier host logs showed Intel GPU invalidation timeouts. Causality with Floatdesk was unresolved.
- Pinch-drag/release and rapid gesture sequences were reported around earlier crashes. No retained trace establishes pinch timing as the cause. Reproduce while tracking video and material activity from the same process.

For each recurrence, run `python3 scripts/xr-crash-report.py` outside the sandbox before clearing logcat or relaunching. It pairs the crash-buffer stack with the `FloatdeskNative` journal lines from the same PID; the journal records each native operation before it runs, so its last lines precede the failing call. Otherwise capture a bounded crash-buffer stack and the preceding pane create, resize, present, hide and release events. Record app build, PID, projection mode, capture owner, child and surface generation. For a native material abort, correlate both the failed ID and the desktop shape submissions following first presentation.
