# Floatdesk XR regression requirements

This records the latest intent from the long headset test session. Later directions supersede earlier experiments. The user has repeatedly asked to preserve working behavior when changing nearby code.

## Desktop, projection and depth order

- Keep the desktop visible on startup and after Reset, resize, mode switches, reconnection, Workspace close and headset/host sleep. Start with the view centered. Recover corrupt saved transforms without deleting valid settings or supporting placements. Normalize composed rotations and reject invalid geometry before native submission. Check video output and scene placement independently. Reacquire Full Space until both XR lifecycle and spatial UI are available. A remounted scene must retry root discovery if a surface is reported before parenting.
- Spherical projection is required for all scene elements that participate in the desktop's flat/curved setting. Use the same mapping at startup and on mode switches. In curved mode the viewer is at the sphere center, apparent angular spacing stays consistent, and the portion in front of the head looks locally straight. Head orientation steers curvature. Gaze steers high-resolution streaming independently. Preserve orientation, aspect, UV coverage, native sharpness and matching visual and logical bounds through both directions of projection switching, even on very large desktops.
- Desktop, magnifiers, panels and shell menus, and the diagnostic overlay are ordered from farthest to closest. Fit the entire popup silhouette within the foreground radius of its magnifier, preserving apparent angular position and size. Compute this from the submitted owner geometry, including curved triangle chords. Enlarging the spherical desktop must never bury foreground objects. Rotate or translate the headset and test both edge and central overlaps. Keep input priority consistent with visibility.
- Depth sorting of separately composited external video has failed in practice. The prior working approach used desktop mesh apertures under foreground surfaces. Only admit panes that have presented opaque content and use their submitted geometry. Keep surrounding desktop pixels, respect desktop gaps, and remove stale coverage on hide, Reset, resize or mode change. A pending capture, decorative beam or guessed pane must never punch a passthrough hole. Preserve the original video when a mask cannot be safely applied. Vulkan/Filament crashes have happened during rapid surface allocation and disposal. Reuse surfaces, pace mesh submissions and keep capture/mirror lifetimes consistent. Desktop curved surface creation goes through the same submission gate as shape updates. Creation uploads the initial mesh once.
- Hand beams and layout axes must be real non-intercepting geometry, visible over live video, consistent in color and intensity across screen edges. Use cyan and violet for the two hands. Menu indicators are a faint translucent 3D glow in front of, and just above, the actual target. Align the menu to the window's apparent angle. Keep tip layers next to their buttons without shifting button layouts or causing gaze to move off target.
- Two-hand preview hides the single aiming beam and shows both contacts/tethers. During a grab show the initial held monitor points, the in-hand wireframe and connecting tethers. A grab starts from two valid separated contacts on the same object; separation is angular and does not grow with desktop size. Use the same configured pinch criteria as mouse. Lock the initial transform, avoid teleporting, and match the actual result to the projected preview on release. Aiming, grab preview and release must work on enlarged desktops and at curved edges. Stationary tracked hands should keep aiming without an app timeout.

## Input and menus

- Follow may be latched or driven by a deliberate fist. A relaxed hand must not trigger it. Restore the desktop quickly after a grab snapshot is released and keep the overlay and controls usable during the change.
- Use shared pinch settings and state transitions across desktop, panels and magnifiers. Pinch release uses the same boundary as press for desktop mouse gestures, and quick contact/release needs no dwell to produce a click. Hand Mouse index pinch clicks, repeated pinches preserve multiple clicks, an index hold can drag, middle tap right-clicks on release and middle movement scrolls without a fixed wait. Scrolling is stabilized and reversed by default with a setting. Thumb plus index and middle is distinct where supported. Mouse pinch and palm activation are separate contexts, use different tuning when necessary, and remain independently adjustable. Drag locks the aim owner and surface, continues to use captured native MOVE contacts from that owner, and uses wrist motion when native motion stops. Wrist positions must be transformed from perception space into the desktop root before constructing a ray with eye and contact positions. During a drag the hand beam uses the live drag-ray contact and never falls back to the pinch-start marker. It continues across native hover loss and releases without a cursor jump or a stuck host button.
- Hand Mouse is a global toggle for desktop and supporting objects except the desktop reference. Eye Mouse was removed. Tap to focus and Drag to move are independent default-on toggles on the desktop reference. Hands off temporarily suspends all three without changing their preferences. Two hands reserving an object suppress ordinary focus/click gestures. Layout mode gates focus, window grab, and their menus; resize handles appear only in one-hand layout.
- Gaze to focus activates without raising, including gaze over a magnifier. Suppress it while typing and for the configurable quiet period, indicated subtly on the locked window. Native hand/eye input can coexist where the OS supports it. The app ray should remain usable with tracked stationary hands; doubled hands and boundary/low-light failures have also happened outside Floatdesk. Do not claim the app can override system boundaries. Aim to hover must never create or remove XInput master keyboard/pointer devices; removing the old master pair crashed the Plasma session.
- Focus uses the desktop's authored home position, fits the complete selected region inside the central view, and moves the host cursor to the pinch point. Tap-to-focus selects windows with index, screens with middle and supports whole-desktop Reset. Selected windows can raise on explicit focus. Gaze focus does not raise. Focus no longer adds a temporary Follow period.
- Window grab can start anywhere on the window, including an OS-snapped window after unsnapping it. Show source and target rectangles, stabilize hold vs drag, snap to the work area excluding panels, and send geometry only on release. Window actions have icon-only minimize/close, a separator and visible, square, highlighted grid choices. Drag within a grid to span several cells. Keep the grid open through drag and while aim or gaze is inside; dismiss when both leave or on an outside tap. Fit the entire menu hit surface in front of its curved target. Magnifier controls belong in a separate adjacent menu. The final fixed magnifier cannot be deleted; offer switching magnification off.
- The palm panel appears on a deliberate palm-facing gesture, supports other-hand direct touch and same-hand middle pinch on a gaze-highlighted button, regardless of desktop eye settings. Keep it within touch reach, size labels to fit, and give successful taps visible feedback. Main and Layout stay single-page, with actions grouped by purpose and small category labels. Preserve the Edit pencil and user layout. Editing holds the panel open, gates normal actions, captures the specific item under the initial pinch before testing movement, then snaps buttons and labels to the same half-button grid. Labels snap within a single grid row at the original 11 sp size. Tapping edits the label in place, and the keyboard’s Done action applies it. A missing palm, transient hand tracking, or renderer remount must preserve the edit session and draft. Save and cancel are explicit. Save the two pages independently and use the saved geometry for native, gaze and touch hit tests. Keep Hands off and interaction switches accessible.
- Settings is a gear on the palm menu. Workspace is a section of Settings. Keep controls contextual, stable and compact. Keep a backed Close cross and important status fixed while the content scrolls. Use a numeric keyboard for numerical fields. Spawn Settings in front or hide the desktop while it is open.

## Placement and connected mouse space

- A workspace-wide origin and axes are independent from the desktop. Moving the origin during Layout changes the coordinate frame while other objects stay placed. Moving the desktop changes only that object. Reset returns the entire arrangement to view, restores desktop framing and maintains its authored home. Entering Layout restores unzoomed framing before edits. Remember placements across restart and tracking recovery. Support undo/redo, arrangement history and save slots accessible from Layout; show the diagnostic 2D map in Layout.
- Layout menu controls one-hand angular auto placement and two-hand free placement. One-hand movement faces/aligns the desktop with the current head and applies the relevant shared alignment to other objects. Free placement activates only on two contacts on the same object and preserves authored orientation. Origin spheres keep constant apparent size, remain grabbable, and the stable straight/curved axes pass through them without stealing aim. Keep cyan near and violet far guides. Arrange exposes Align, Snap, Face and adjacent Auto. Snap sequentially from closest to the desktop with minimum displacement, eliminating gaps and overlaps against snapped objects. Preserve support-object placements during focus adjustments and desktop-relative arrangement in window-grab context.
- Mouse topology is axis-aligned 2D workspace space, independent of head pose and visual curvature. Front overlap wins. Shadows are drawn on all overlapping back planes and must not drift with the headset. Move across aligned gaps only along the crossing axis, never diagonally. Clamp at outer boundaries when no space is available in the crossing direction. Keep the real cursor's space and logical coordinates on magnifiers/panels when their content changes, map separately to the host and show mirrored cursors distinctly. The real cursor uses a separate, fixed-angular-size scene marker. Derive its position from host pixel coordinates on the visible surface. Use the submenu indicator’s translucent spherical glow at lower opacity and constant apparent size. Keep it on the owning pixel’s view ray. For supporting panes, clear both the submitted surface’s nearest depth and its native ordering origin. Scale with marker distance to preserve apparent size as depth changes. Preserve the user’s cyan cursor glow and tune visibility separately from the submenu indicator. The headset media surface exposes alpha compositing and no spotlight that affects the texture. Use the host’s cursor owner key and the submitted pane for placement, including for captured child regions. Suppress the competing native marker. Resolve curved native hover using the hit event’s transform and the submitted sphere, then reject contacts outside the aperture. Use a root-space ray for captured moves with missing native hit data. Do not fall back to a differently transformed coarse collider hit on a miss. Use the authored footprint for the axis-aligned map. Draw regular cursor sprites after companion-window capture composition using the crop that owns the pointer. Switching hand aiming off must stop hand-driven cursor movement.

## Magnifiers, capture and streaming

- Gaze to magnify and Aim to magnify share dwell and pinning behavior. A window with an explicit X11 transient owner selects its owner group. Reuse the capture atlas and region surfaces for companion windows. Do not infer groups from app class, process ID, or overlap. Keep independent browser windows separate. Companion regions use the same fixed native mesh lifetime as context menus. Mountlet and pane re-enable failures showed Android XR SplitEngine unknown-material aborts. Bind curved support input to a retained triangle collider derived from the submitted video geometry. Direct custom-video-surface input regressed hand aiming. Keep collider and video visibility together and detach both without explicit disposal. Retain the video’s native mesh across hide/show and ordinary pose updates. Allocate an immutable replacement when size changes materially. Gate new pane surfaces with desktop mesh submissions and give texture initialization a separate interval before attaching input and video producers. Coalesce provisional child dimensions before allocating a curved native surface. A stable child reuses its submitted mesh.
- Magnifiers keep authored positions/sizes between restarts. The floating mode was removed. Magnifiers keep their configured radial order with the desktop and match visual hit bounds. Move in angular directions during layout, and keep corner handles at actual corners for resizing. Flat magnifiers should not tilt continuously with sideways head movement. Show the pin frame outside the image, pin through the magnifier menu, and keep move separate from pin. Hide magnifiers when Workspace opens.
- Do not sacrifice magnifier image quality to address heat. A 30 FPS cap is acceptable; reuse live high-resolution frames for magnification and desktop detail where possible. Preserve foreground detail when no standalone magnifier is enabled. Avoid covering unrelated foreground windows or erasing desktop pixels on capture failure. Use dwell and tracking tolerance so blinks do not switch the displayed window.
- Render taskbars, system launcher, context menus including overflow, and taskbar preview windows from the right live capture. Place menus next to their panel or owner at foreground depth. Crop vertical and horizontal panels consistently; no excess margin or stale preview from the previous taskbar icon. Mixed single/multi-window previews use the same scaling and update their real placement and bounds.
- One combined headset desktop follows the host's multi-monitor arrangement. Do not stream stale pixels in desktop gaps. Visual spacing is independent of logical screen adjacency and should allow fractional settings. Dynamic quality is experimental, gaze-driven and adaptive. Preserve high-resolution coverage near gaze, useful peripheral quality and timely frame replacement. Prefer a visible crop and shared capture work, avoid visible seams and layout-dependent loss of baseline sharpness. Keep encoder quality, sharpening, bandwidth and regional allocation controls; Auto balances area/background quality against FPS. Diagnostics report CPU with units, thermal state, FPS, background ratio and coverage, remain in front with a readable translucent background and intercept gaze over the overlay.
- Follow an isolated changed frame with one paced frame before skipping static content, so a decoder can deliver its final update. Preserve stream reconnection and automatic layout reload, including low-refresh virtual outputs and sleep. Show progress while reloading, avoid waiting on a fresh render before recovering capture, limit memory and thermal load, and investigate stale frames and native crashes using logs. Keep expensive optional work bounded. Maintain effect and surface lifetimes across pause/resume, curved transitions and Workspace close.

## Host and monitor management

- On X11/Plasma, preserve physical output identity independently of primary designation, preserve priorities while rearranging, and provide virtual-output setup through the host/tray. Use the lowest valid virtual refresh rate independently of stream cadence. Support disable-all/restore shortcuts in both apps and persist that choice. Keep resource estimates and current pixel counts visible instead of fixed limits. Restore per-screen add, resolution, resize and remove controls.
- Workspace layout preview tracks gaze selection, remains centered as the arrangement changes, snaps at edges and half-points, and ignores last-moment pinch-release drift. Reject overlaps and displays disconnected from the primary. Apply staged edits inside the editor. Host-side changes trigger reload automatically. Keep tray polling and display queries cheap and prevent Qt/IBus churn; use current/cached XRandR state where applicable. Connection recovery should tolerate host hangs, VPN changes, restart and sleep; Wake-on-LAN depends on host configuration.

## Verification

Run `python3 scripts/verify.py --group jvm --only jvm-focus_interaction --only jvm-gestures --only jvm-workspace_regressions` for input, placement and video-geometry changes. Use the Android debug build and a connected headset for compositor, gaze, native drag and sleep verification. Exercise normal and enlarged flat/curved desktops with every supporting surface overlapping. Test after Reset, release and restart; watch for visible passthrough holes, frozen capture, misplaced guides and stale hit areas. When possible use an existing repro alongside a unit check, since many of these issues depend on the Android XR compositor, tracking or X11 behavior.

- A saved magnifier keeps its video surface and input collider when the captured window changes aspect ratio. Fit curved panes via a centered transparent aperture in the retained sphere. Preserve the viewer as the center, and restrict the collider to the visible image. Fit flat panes through transforms. Route support Hand Mouse contacts using their original host coordinates. Only an authored resize or projection change can require new native geometry.
