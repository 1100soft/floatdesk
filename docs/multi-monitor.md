# Dynamic desktop screens

Open the palm panel, choose **Workspace**, then use **Screens**. Add creates a 1920 × 1080 output; edit its resolution under that output. Resolution menus come from the host's advertised modes, and custom dimensions can be entered. The host attempts to register missing virtual-output modes with cvt/XRandR and reports driver rejection without silently changing dimensions. The host always selects the lowest advertised positive refresh rate, including sub-Hz rates. Screen configuration runs on a dedicated worker with a 120-second subprocess timeout; a long low-rate modeset does not block the control loop, packet repair or heartbeats. It may still temporarily interrupt X server capture. “Updating screens…” stays visible while configuration/recovery completes.

The arrangement editor centers the layout with room around every edge. It snaps shared edges and half-screen positions and rejects overlapping or orphaning changes. External arrangement changes reload automatically after stable observations.

Run the host with `serve --existing`. It reads active XRandR outputs and captures their bounding rectangle as **one desktop object**, preserving the system arrangement, including vertical offsets, gaps and overlaps. Two 1920 × 1080 outputs side by side produce one 3840 × 1080 screen. Stacked outputs produce a taller screen. Moving, resizing or spherically warping this object applies to the complete desktop, with no seams between independently projected screens. Mouse coordinates map across the original desktop rectangle.

The single H.264 stream fits within 4096 × 2160, preserving aspect ratio to even-pixel precision. Larger desktops are downscaled; the actual system output resolutions and pointer coordinates remain unchanged. This trades fine text detail for bounded encoder/decoder dimensions. The Screens panel distinguishes streamed dimensions from the per-output resolutions and still manages each added desktop output separately. Capture cost grows with the full desktop area even when video is downscaled.

Adding/removing/changing resolution rebuilds capture and decoding; a brief video interruption is expected. Refresh rereads the system arrangement. The combined object keeps its historical canvas identity (`existing-0`) and its saved pose/physical width; height adapts to the combined aspect ratio. Older independent placements disappear from the active layout. Saved layouts store placement, not an instruction to recreate desktop outputs automatically. Legacy `serve --monitors` logical-region mode remains separate.

## VKMS pool

The supplied `vkms_flexible_monitors_kde_x11.ipynb` is reference material, not an installer executed by Floatdesk. Its configfs service provisions independent VKMS connectors/CRTCs before Xorg, links the provider and advertises modes. This machine already has four inactive `Virtual-1-*` outputs. Floatdesk activates that pool through unprivileged XRandR commands; it does not run notebook cells, use sudo, rebuild modules, change boot configuration or reboot.

This produces real KDE desktop outputs, unlike RandR logical monitor regions with no backing output. Use **Screen setup** for readiness checks and a reviewable installation bundle; see [virtual-display setup](virtual-display-setup.md). Creating a larger kernel/Xorg pool remains an administrator setup step before the graphical session starts. If no unused `Virtual-*` output exists, Add is unavailable. The current implementation supports X11 and numeric `Virtual-*` output names. The host attempts automatic preparation of an accessible backend; first-time privileged boot setup is available through the tray. Wayland is not supported.

Physical and already-active outputs are included in the combined desktop but cannot be resized or removed from the app. Only outputs added by the current Floatdesk host process are manageable. New outputs start to the right of active outputs. Existing positions survive addition, resolution changes and removal; use the editor to close gaps or correct overlaps. Position edits may move physical outputs when explicitly dragged, but never change their modes. The editor permits drops past the current top/left edges. The host translates the complete proposed arrangement back to nonnegative X11 coordinates in one transaction, preserving relative placement and priorities. Existing desktop windows may be rearranged by KDE when outputs are added or removed.

Added outputs remain active across headset reconnects and are disabled on graceful host shutdown. Host service restart ends that ownership session. SIGKILL, power loss or a crash can leave outputs enabled; disable those specific virtual outputs in KDE Display Configuration before restarting if they should return to the available pool. Floatdesk does not adopt or disable pre-existing screens automatically.

## Control and validation

Monitor commands carry request IDs and are accepted only from the connected control peer. The host caches replies so retransmitted Add requests do not create duplicate screens. Dimensions and action/index values are bounded. Timed-out requests are reconciled by an automatic read-only refresh before another change. This uses the existing trusted-LAN UDP transport, without authentication or encryption.

Validation includes Rust parser/protocol tests and `checks/monitor_management.py`, which checks Android/Rust wire fixtures and pose preservation through source changes. A live X11 test exercised two additions, retry deduplication, resolution change, index compaction, removal and graceful cleanup, receiving RTP on three independent ports. The physical display configuration matched its starting state afterward. The user confirmed adding, resizing and removing outputs in the headset; existing-desktop mode now uses one combined decoder rather than independent per-output decoding.

Gesture reliability remains deferred in [gesture-issues.md](gesture-issues.md); this work does not tune gestures or change the confirmed monitor coordinate conversion.

## Native renderer lifetime fix — 11 November 2026

The first device test confirmed screen management worked but reported repeated crashes. The crash buffer showed native Impress/SplitEngine aborts for unknown material instance IDs. Review found that curved colliders and frozen images detached their entities and immediately closed the model; detachment does not synchronously destroy the native instances. The same pattern existed in grab-guide shutdown. This is the leading explanation for those material errors, pending another device test.

Owned glTF teardown now explicitly disposes native instances before closing their backing models, using the pinned SDK's restricted disposal API, which also clears its automatic-cleanup reference. Curved collider close is idempotent. A collider that finishes loading after its monitor owner has closed is immediately released and cannot disable or replace the restored input owner. The resource lifetime check exercises repeated close and failed construction with native-lifetime substitutes; the warp check covers late completion. These tests cannot establish that a native renderer crash is eliminated on hardware.

## Readback and packet repair

Larger desktops are downscaled into an XRender offscreen pixmap before MIT-SHM readback when supported, with a full-desktop/software-scaling fallback. Logical desktop coordinates remain full resolution. Cursor position, shape and hotspot are scaled into the captured frame. On this machine's 5120 × 3200 desktop, a read-only 15-frame comparison measured roughly 53 ms/full readback versus 26 ms/scaled readback. This measures capture cost, not guaranteed streaming FPS. A private synthetic Xvfb check verifies crop, colors, child windows and output dimensions.

The host retains the latest 2,048 RTP packets in memory for bounded repair requests from the connected control peer. Requests must match the active stream/source and are rate-limited to 64 per 100 ms. The client requests missing packets within a 60 ms reorder window, including a missing final fragment on an otherwise static screen; unsuccessful tail repair falls back to keyframe recovery after 200 ms. Late packets from recently retired sources cannot switch a new stream back to an old one. The decoder also requests recovery if initial codec parameters are absent.

Automated checks cover exact repair wire layout, same-ID retries/read-only reconciliation, independent connector/primary metadata, repaired fragments/tails, old-source rejection, cursor scaling and byte-identical network retransmission with unauthorized-peer rejection. Rust workspace tests, Android build/lint and private offscreen device checks supplement these tests. The user subsequently confirmed much smoother videos and pointer movement. Reload-indicator placement still needs user confirmation; packet repair does not eliminate sustained congestion or hardware limits.

### Sub-Hz configuration delay

A final full-resolution restore exposed a 2560 × 1600 sub-Hz mode which Plasma labelled `@0`; its configuration transaction exceeded the interactive timeout and partially enabled the output. The previous policy excluded rates below 1 Hz; this was superseded by the lowest-rate worker implementation below. The ten-second flip wait is now handled without raising the requested refresh rate. A new output is claimed before a Plasma transaction so a partial/uncertain application remains manageable and can be cleaned up.

The host also handles SIGTERM/SIGHUP through the graceful shutdown path, so normal user-service stops release app-owned virtual outputs. This does not make crash leftovers automatically owned: deliberate restoration of the current task's screens re-established management while preserving the verified user layout, primary and priorities.

## Connected layouts and transparent spacing — 12 November 2026

App layout changes must keep every screen connected to the primary through shared edges, without overlapping area. Corner-only contact is insufficient. Overlaps, including mirrored rectangles, are rejected for app edits. The editor marks invalid drops red and cancels them; the host independently validates moves, additions, resolution changes and removals before changing the system configuration. Removing a bridge screen is rejected. A pre-existing disconnected layout created outside Floatdesk can be repaired one island at a time, provided each change reduces the number of orphan screens. Floatdesk does not silently rearrange external configurations.

Unused areas of the combined desktop are transparent in both live video and grab snapshots. This uses output rectangles rather than a black color key, so black content on a real screen remains opaque. **Visual spacing** in Workspace uniformly insets each screen around its center, preserving its aspect ratio, without moving logical desktop edges. The percentage is the reduction of each screen’s width and height, split equally between opposite edges: 10.0% leaves 90% of each dimension, with a 5% inset per edge. The slider and saved setting use 0.1 percentage-point steps, matching the displayed decimal precision. The setting is saved in the workspace. Pointer coordinates are remapped to the displayed content; visual gaps do not aim the desktop mouse. The combined monitor's outer frame and manipulation geometry remain one object.

The compositor applies the mask and spacing in its existing GPU pass, without another decoder or CPU frame copy. JVM checks cover layout connectivity and inverse pointer mapping; the offscreen device check covers transparent gaps, opaque black content, source orientation and presentation updates without a new video frame.

### Fixed Workspace information and quality limits

The close control has a filled circular background. Status, Add/Refresh/setup actions, exact content-pixel totals, capture size, current stream dimensions and source-to-stream scale remain fixed above the scrolling arrangement/resolution controls. Error status remains fixed too.

The host still captures the complete bounding rectangle, including gaps. Clearing gaps and making them geometrically transparent on the headset does not pack the transmitted image. Scale is `min(4096 / sourceWidth, 2160 / sourceHeight, 1)`, with even-pixel rounding. Increasing height past 2160 reduces detail in both axes even before the width ceiling is reached. The current headset's vendor H.264 decoder declaration advertises up to 4096 × 2176; simply removing the height bound is not a valid quality fix. Packing occupied output regions into a texture atlas and reconstructing their arrangement on the client is a prospective optimization, not implemented here.

Spherical mode now uses head-directed geodesic vertex mapping on a viewer-centered sphere, described below. It moves the least-distorted region with the view; it does not remove global spherical distortion or restore detail already lost in video downscaling. Projection reference: [PROJ gnomonic projection](https://proj.org/en/stable/operations/projections/gnom.html).

### Low-rate layout transactions and pinch release

The asynchronous display worker keeps network work out of the KScreen command, but does not eliminate driver modeset waits. A live KScreen move that changed desktop bounds took 93 seconds at sub-Hz virtual refresh. Position edits now use one guarded native RandR transaction: snapshot active CRTC modes and positions, suspend virtual scanout, change the framebuffer once, then restore scanout at the original mode IDs. Moving physical outputs suspends only those physical CRTCs that actually move. The server grab prevents desktop clients from querying an intermediate disconnected layout; it is released on failure too. Partial errors attempt to restore the original framebuffer and every touched CRTC. Root DPI, output primary and priority properties are retained. Mirrored outputs with conflicting requested positions fall back to the desktop backend.

A live production-path move expanding desktop bounds took 6.2 seconds and restored the original layout, dimensions, rates and primary. The installed host control path acknowledged another bounds-changing move in 8.7 seconds; restoration preserved layout, primary, priorities and ownership. This is a substantial reduction, not an instantaneous modeset guarantee: the driver can still wait for pending low-rate scanout work. PRIME synchronization was compared separately and did not eliminate the wait, so the test settings were restored. Add/remove/resolution operations still use the existing desktop backend; the native fast path currently covers position edits only.

Drag preview remains live. On release, the arrangement editor commits its sampled position from at least 100 ms before the input UP timestamp, discarding final pinch-opening aim movement. It retains at most 64 samples and clears them between drags. Checks cover release jitter, a deliberately held destination and reset between gestures.

Per-screen GPU copies into a single packed video atlas are the preferred next streaming step. They can reuse one encoder, one decoder and one GPU assembly pass, reducing transmitted gaps. Packing must also respect codec width/height limits: a tall, fully occupied desktop can still lose detail even without gaps. Independently encoded fine tiles add codec contexts, queues and synchronization; their overhead has not been measured here. A low-detail base plus view-dependent detail tiles could improve the viewed region, but requires atlas metadata, inverse hit mapping, rate allocation and latency/resource measurements. Neither atlas streaming nor adaptive detail is implemented by this layout fix.

The native live regression is explicitly opt-in because it temporarily moves a real output: `FLOATDESK_TEST_LIVE_ARRANGE=1 cargo test --offline -p floatdesk live_move_and_restore -- --ignored --nocapture`. It requires an available virtual output with room for a 64-pixel horizontal move and restores the starting layout before asserting results. Routine host tests leave it ignored.

### Dynamic projection and tracking-loss recovery

Spherical mode changes the actual surface vertices using a spherical exponential map, not full gnomonic projection. A full gnomonic map made every image edge straight in perspective and caused the entire desktop to read as a planar panel. Radius checks and all-edge straightness checks were insufficient to reject that behavior.

Given eye center E, radius R, viewed source coordinate f, transported tangent axes tX/tY and inward focus direction -n, let `u=k(x-f.x)`, `v=k(y-f.y)`, and `s=sqrt(u*u+v*v)`. Set `a=s` through 1.5 radians; beyond that, use `a=1.5+b*(1-exp(-(s-1.5)/b))`, where `b=π-0.01-1.5`. Vertices are `E + R[-cos(a)n + sin(a)/s*(u*tX+v*tY)]`, using the unit limit at zero. Reference focus positions use the same exponential map centered at the original desktop center. Parallel transport makes the original center remain fixed for every focus. The map is bounded below the antipodal fold.

The axes through the viewed point are great circles and project to straight lines. Peripheral constant-x/y lines retain curvature. Tests now require BOTH focused-axis straightness and curved peripheral edges, along with constant eye radius, an anchored center and changes in inter-vertex distances that rule out a rigid rotating panel. The stabilized fine-gaze direction is inverted analytically through the reference sphere's log map, so looking at or past the old rectangular boundary can still focus an edge. Flat mode is explicitly checked for unchanged pose/geometry under head-direction changes.

Texture-only correction remains disabled; original UVs and pixels are used. Video, snapshots, pointer inversion and two-hand contacts share the geodesic geometry. Updates are bounded to 10 Hz. Mouse and native-handle interactions freeze the mesh; custom spherical grabs show the projected result through the deformable snapshot described below. The backing move/resize rectangle stays on the original behind-sphere tangent plane and includes the complete curved perimeter in its bounds. It does not rotate into a head-facing flat panel. Its bounds are cached per mesh, and tiny size changes from floating-point roundoff do not replace native materials/affordances.

Native collision uses one reusable asset containing 192 triangles, represented by 384 transform nodes sharing one unit triangle and one transparent material. Each triangle is updated through two rotations and diagonal scale (2D SVD), preserving its three target corners without bounding rectangles protruding outside the outline. No native GLTF model/material is loaded or destroyed for head-direction updates. The grid stays allocated but disabled in flat mode and is reparented/re-enabled on return. Its coarser chordal surface only acquires native events; the event's actual origin/direction are transformed with its hit matrix and intersected with the rendered video triangles. Coarse-collider hits are not rejected for lying inside the ideal sphere. This preserves contact positions instead of treating an approximate collision-plane hit as the visible surface.

Checks cover changing vertices, constant radius, straight focused axes plus curved peripheral edges at left/right focus, exact reconstruction of every collider triangle's corners from its transform hierarchy, inverse ray coordinates, stable collider-model identity, freeze/resume, source orientation, behind-image frame clearance, perimeter containment, transparent holes and dynamic snapshots. The collider asset is parsed to verify one shared triangle/material and bounded size. Offscreen headset tests validate video/decoder behavior; native node hit testing, visual comfort and prolonged XR stability still require using the installed app.

Earlier projection experiments repeatedly replaced native interaction models. Retained logs include a System UI failure in XR material destruction; that fault also predates these experiments, so causation and a full-device reboot are not established. The reusable transformed geometry removes that repeated model/material lifecycle from head turns.

Tracking recovery remembers the last trusted viewer pose. After at least 250 ms of unreliable head tracking, recovery at a pose displaced more than 25 cm or rotated more than 0.5 radians rebases unanchored workspace layouts from the previous viewer to the recovered viewer. It cancels custom grabs and clears pointer state before continuing. The existing tracking guard requires stable tracking for 300 ms before accepting recovery. Ordinary motion, brief gaps and small drift do not rebase. Anchored workspaces retain their anchor policy. A callback for an explicit activity-origin change still takes precedence. This mitigates lost-screen recovery; the app does not suppress system tracking warnings or repair unavailable room tracking.

View-dependent streaming is a separate optimization: send the visible desktop regions with a guard band/prefetch for head turns, omit off-view high-detail pixels, and assemble a packed atlas using the same logical desktop coordinates. Selection/assembly overhead can be outweighed by lower capture, encode, network and decode work. Measurements must separate those stages and report total motion-to-photon latency, including newly exposed-region recovery. Independent streams per tiny tile are not required. Current host counters do not identify which stage dominates, and this projection update does not yet crop or reprioritize transmitted regions.

### Multihomed discovery and a stuck Updating screens indicator

On a computer with Wi-Fi and Ethernet on the same LAN, the first broadcast beacon can use the Wi-Fi address while unicast control replies use the Ethernet route. The old client pinned the first beacon address and rejected the host hello/status replies from the other interface. Live inspection showed zero decoders, an empty monitor catalogue and a pending screen query despite the host still encoding. Selecting the actual reply interface immediately started video reception and resolved the query; no screen arrangement or host stream change was needed.

The client retains up to 32 advertised endpoints for 10 seconds. Before connection (or after five seconds without an accepted hello), it retries fresh endpoints advertised under the selected host name every 2.5 seconds. A healthy connection stays pinned, and received hello/status messages still require the selected address/port. The initial broadcast handshake records the actual reply port. Discovery continues observing beacons after the first selection. This is the existing unauthenticated LAN discovery model; matching names is not cryptographic host identity.

Beacon receive timeout is 1 ms rather than 200 ms, preventing discovery polling from delaying every control datagram. Checks exercise actual wildcard UDP replies from a different loopback interface, strict endpoint matching, fallback, healthy-peer stability, expiry, unrelated host names and disconnect reset. Existing display-request checks retain same-ID mutation retries and read-only reconciliation after uncertainty.

### Large desktop resize and beam consistency

A device inspection found a 5.36-unit resize frame with a maximum width of only 3.87 units: the old 2.4 × 1.5 desktop ceiling conflicted with uncapped two-hand enlargement. Native bounds now grow with the current frame (a finite 16× per-gesture envelope, with a 10-metre baseline). Shared preview/release sizing preserves aspect and minimum size without that fixed upper ceiling. A missing or invalid final native proposal retains the last valid size and always releases resize ownership so geometry can synchronize.

The geodesic renderer inherited a conservative 2.2-radian envelope from the older projection. The active path skips that recurrence and uses the peripheral angular compression described above, approaching the antipodal boundary without a fixed physical desktop-size ceiling. Legacy reference geometry retains its original envelope.

Aiming beams reconstruct their surface endpoint from retained source UVs and the currently rendered mesh dimensions, then apply the existing eye-directed foreground bias. They do not reuse a pre-resize 3D contact or assume pending logical dimensions have already reached the renderer. Regression checks cover oversized resize bounds, invalid END recovery, the recorded angular-limit crossing and beam endpoints across large curved/flat surfaces. These synthetic checks do not replace headset visual confirmation.

Wraparound geometry uses a finite orthographic backing frame; tangent-plane perspective bounds are undefined at the horizon. An intermediate focus clamp was removed because it prevented view-centric curvature near full coverage. Active geometry now preserves local angular scale through 1.5 radians and smoothly compresses farther radial distances toward π−0.01. Focus is unrestricted within the desktop, and its inverse uses the same radial mapping. This deliberately sacrifices equal peripheral angular spacing to retain local view-centric curvature without spherical overlap; physical radius remains constant. The beam endpoint now uses barycentric video-triangle depth rather than the normalized ideal sphere, before the existing visibility offset.

Two-hand acquisition and preview now require five degrees of separation between the viewer-to-contact directions, replacing the 18%-of-desktop-width minimum. Physical hands still need 9 cm separation to avoid unstable gain. Source UVs resolve against current video triangles in preview and joint-confirmed acquisition. If both tracked index pinches are closed over the same monitor, the validated contacts can complete a pending pair without waiting for a missed native DOWN. Release rearming, tracking-loss cancellation and motion-discontinuity guards remain in force. Regression checks include a 20-unit-wide desktop and a pending pair completed without a second native event.

### Shared input and large-surface regression investigation

Grab state, angular acquisition policy and preview construction live in `GrabInteraction.kt`; `MainActivity` coordinates tracking and rendering. Grab contact and mouse index contact now call the same binary `indexPinchClosed` function. The obsolete 40 mm grab-only threshold is gone. Native events cannot initiate a grab without physical contact, nor release it while both tracked contacts remain closed. Physical opening, missing samples and discontinuities still cancel. Rearming records each hand's physical opening independently. A delayed UI tick with fresh stable samples no longer counts as tracking loss.

The native interaction grid is coarser than the rendered video. Its flat triangles can lie more than 2% of the sphere radius inside the ideal sphere. The old native-hit correction rejected those valid hits before ray resolution; a reproduction rejects 142 valid coarse contacts across its large-surface cases. Native hover and selection now transform the event's actual origin/direction and use the same rendered-triangle ray intersection as gaze. They no longer require a near-sphere native hit or start a synthetic ray only 4% of the radius before it. Source UV reconstruction and beam endpoints use those video triangles. The coarse native grid still acquires events, so native hit delivery remains a device validation boundary.

Aiming and grab tethers already share the same `surfaceRays` renderer. Active grab video uses a frozen native image; normal aiming and preview use live video and depend on hover contacts. Thus active tethers can work after live-hover rejection removes aiming contacts. Two rays on different monitors now remain independent aiming contacts instead of selecting a preview with no valid same-monitor pair. Beam suppression for native handles uses explicit controller ownership rather than inferring it from the generic manipulation flag, which also represented pending custom grabs. This removes two additional paths to invisible aiming beams. These changes do not establish that every native compositor visibility fault is resolved.

### Projected result during a spherical grab

Spherical grabs now display the current geodesic result while held, rather than uniformly scaling the mesh captured at acquisition. One bounded snapshot texture/material is shared by a reusable 16×10-cell native triangle grid (640 transform nodes). Triangle poses/scales update through the same affine decomposition as the input grid; no model or material is replaced per movement frame. Projection updates during grabs are bounded to 10 Hz and release immediately performs any final synchronization. Flat grabs retain their previous rigid snapshot path. The native snapshot grid is coarser than the 64×40 live mesh, so fine curvature tessellation can still differ, but it uses the same projection and source pixels.

Markers follow the actual projected held source pixels; the virtual-copy hand transform remains rigid and unchanged. Scene panel depth testing is explicitly applied to the session, and solid beam textures now use opaque media blending with translucency through entity alpha. Existing live-video opaque geometry and transparent layout holes remain. These are rendering-path changes following device logs with resolved hover contacts despite invisible beams; they require a device visual check and do not by themselves establish the compositor failure's full cause.

### Reset into the current view

Both Reset controls cancel custom grabs, rebuild the active desktop layout in front of the current trusted viewer and persist it. The layout center is 1.2 metres ahead along the current view orientation, including pitch/roll, rather than at a fixed room coordinate. Uniform scaling fits the complete bounds inside the smaller per-eye horizontal/vertical half-angles, retaining a 15% angular margin. Spherical mode checks corner angles, so fitting the central horizontal/vertical arcs cannot leave corners outside view. Source resolutions/aspect ratios are unchanged. Before valid camera FOV arrives, conservative 70°×60° full-view defaults are used. Tracking-space scale is applied to distance and dimensions.

Outstanding device regression: aiming and preview beams can remain invisible over large live desktops even with resolved hover, explicit depth testing and opaque beam texels. Active-grab native snapshot tethers remain visible. The last depth-path changes did not resolve this; no successful live-beam fix is claimed by the Reset update.

### Screen/window focus interaction mode

The palm mode button switches between cursor control and focus selection; the setting is saved. Focus mode suppresses mouse aiming/click/drag/scroll while keeping two-hand preview/acquisition and native backing controls available. Focus pinches do not depend on the experimental mouse Gestures toggle. Both modes use the same aiming context: two rays on one desktop reserve it for preview/grabbing and block desktop pinch actions. Screen and window outlines are drawn with the live pixels, independent of the unresolved native beam visibility. Index/middle pinch edges use the same saved profile as mouse gestures. Focus captures the target at contact and selects on release, with no minimum hold. Initial held pinches do not select until opened; palm/workspace controls, uncertain tracking and pending selection block selection. Aiming with one hand and pinching with the other works when one target is available.

The host advertises EWMH window support and visible client-area rectangles in topmost-first order, without titles. It excludes docks, desktop windows, hidden/minimized windows and other desktops. A background observer collects metadata every 500 ms; regular Workspace metadata publishes it without blocking the input loop. These are bounds for the already streamed combined desktop, not separate per-window capture streams. Hosts without EWMH support retain screen targeting; focus selection requires the updated host. Visual screen spacing is inverted for hit selection and applied to each highlighted rectangle.

A focus request identifies an existing visible window ID or active output name. The bound host validates the target, sends EWMH restack/activation requests for windows and places the mouse at the ray contact captured at pinch-down (clamped to the validated target). Original request IDs are cached, so UDP retries return the acknowledgement without reapplying focus. The headset reframes only after a successful acknowledgement. Focus fits reuse Reset geometry but cap the target to a central 36°×24° region inside the binocular FOV, preserve the rest of the combined desktop, and store the selected source center. Spherical radius and transported axes are relative to that center, avoiding a flat-only recenter that changes again on spherical reprojection. Reset returns to the ordinary desktop center.

After selection, a three-second Follow lease is added to the existing Follow/fist behavior. It does not change the manual Follow toggle: previously off returns off; previously on remains on. Manual Follow changes and Reset can cancel the temporary lease.

Review of the subsequent beam experiment removed its hard-coded 1.5-metre threshold, projected video-beam sampling and unsupported success claims. Only its per-segment GPU color support was retained for focus outlines, with a real device pixel test. Native large-desktop beam visibility remains unresolved.

For the installed host upgrade, `FLOATDESK_RESUME_OUTPUTS` provides a one-time explicit handoff of named, currently active virtual outputs. It excludes physical, inactive and unknown outputs and is consumed once per process, so display-worker placeholders cannot duplicate ownership. This allows replacing the host process without disabling scanout or rearranging windows. The live upgrade retained all three managed outputs and their existing modes, positions and priorities.

### Shared pinch policy and deterministic gating

`PinchPolicy.kt` defines one saved per-hand profile for mouse, focus and two-hand acquisition. Workspace → Settings → Pinch thresholds edits these distances; legacy values are migration defaults rather than independent mode-specific thresholds. Each controller reads a single profile snapshot per update. Palm-panel pinch remains independently tuned. Focus selection fires on release, does not veto a middle pinch because the index rests near its contact boundary, and observes opening while blocked so a block cannot silently require another wide opening.

The input queue formerly discarded the entire batch if its first frame was older than 120 ms, including fresh taps at the end. It now cancels the stale prefix and processes fresh edges. Fist classification and missing non-pinch fingers no longer erase otherwise valid pinch samples; explicit finger contact takes precedence over fist Follow. Fresh tracked-hand gestures are independent of head tracking availability. Native handle ownership is cleared on physical release even if SDK END is lost, with a short acquisition grace for event/sample ordering; controller errors clear ownership and retry rather than leaving a permanent block. Focus diagnostics log the remaining gate reasons and actual shared settings when they change. Palm/workspace controls and uncertain hand identity still deliberately block desktop actions.

Android XR's [SceneCore documentation](https://android.googlesource.com/platform/frameworks/support/+/cedecb539e584a956c3e164a2daa918555b58703/xr/scenecore/scenecore/src/main/java/androidx/xr/scenecore/Scene.kt) documents a developer setting that disables boundaries. The app API exposes consent state, not an override or a way to relocate the system-tracked viewer. No global boundary setting is changed. Existing workspace recovery rebases unanchored content after tracking/origin discontinuities; regression coverage includes a large vertical floor-origin jump. That restores Floatdesk content, not the OS's localization or boundary warning.

### Experimental view-dependent H.264 streaming

The saved, default-off Settings switch enables a persistent TCP view stream on the host's control port. It replaces the earlier JPEG overlay experiment. The host checks the bound client IP and current session ID on each bounded request; headers are limited to 1024 bytes and compressed access units to 8 MiB. One request and one encoder submission are in flight. The ordinary UDP stream remains the fallback.

View coverage clips the actual rendered mesh triangles against all five head-frustum planes and interpolates source UV at the cuts. The earlier cell-based code kept complete cells crossing the eye plane, causing distant sphere regions to expand the crop. Regression coverage includes a large sphere viewed at an off-center corner. A 5% tangent-space guard margin accommodates tracking/delivery latency. Screen spacing is inverted to source coordinates; an independent fine-gaze ray chooses the dense region within the visible crop. Crop updates run at up to 20 Hz while video frames can continue at the configured host rate (up to 60 Hz).

XRender captures/scales two regions directly: a high-density center (configurable 20–65% of crop width/height; default 35%) into the top 2048 × 1024 pixels of a 2048 × 1536 atlas, and the whole visible crop into the lower 2048 × 512 peripheral tile. Gap masking and the cursor are applied to both regions. No full-desktop capture is used to build this atlas. The source rectangle is a conservative axis-aligned view bound, including the guard margin and any gaps within it. Pixels beyond that crop are omitted. One persistent H.264 encoder handles the fixed atlas; no encoder restart is required for head movement.

Every access unit is sent with its exact outer/inner source rectangles and desktop bounds. Synchronous submission/pull ensures the rectangles belong to that compressed picture. The headset validates dimensions, bounds, frame order and session, then associates crop metadata with MediaCodec presentation timestamps. The OES frame callback uses that exact timestamp; unknown metadata is rejected instead of sampling with a newer crop. The existing GL compositor unpacks center/peripheral tiles, feathers their boundary and discards source pixels outside the view crop. Geometry, native input and beams are unchanged. The old JPEG transport and bitmap overlay path are removed.

Successful view frames renew a 500 ms host lease that suspends full-desktop capture/encoding. When the desktop is entirely out of view, a bound-client idle lease suppresses capture. Socket closure, explicit stop, lease expiry, tracking loss, hidden UI or manipulation release the view stream and restore normal video with an IDR. The debug map shows amber outer coverage and a green fresh high-density region/tint, center density gains, transport counters, timings and actual GPU frame count/age. It remains a video-layer overlay with no native input target.

Beam audit against checkpoint `38e3f01`: `GrabGuideRenderer.kt` and `checks/resize_beam.py` retain the checkpoint versions. The saved subsequent agent patch's size-threshold video beam overlay was removed; only per-segment color support was retained for Focus outlines. The checkpoint already recorded unresolved live-beam visibility at large desktop sizes, so reverting the experiment did not establish that visibility or flicker was fixed. The streaming experiment does not alter native beam geometry.

Quality targeting uses the current gaze rays independently of desktop mouse-eye aiming. An analytic plane/full-sphere inverse extends beyond bounded input geometry and the nearest screen's spacing map extends past its edge. This quality-only path never changes mouse or native grab hit testing. A separate filter retains the last target during eye-tracking gaps instead of recentering. Capture is safely clipped to the visible source crop, including very large off-desktop targets. The visible crop still follows the head FOV, since gaze does not define peripheral visibility.

The first H.264 atlas implementation reconstructed detail into the ordinary stream-sized XR buffer, discarding high-frequency detail before presentation. Experimental output now approaches source-native resolution within the reported GPU texture/viewport limit, 8192 pixels per axis and 16,777,216 pixels total. Native surface pixel-size changes leave physical shape/pose and input coordinates alone; EGL output is refreshed once per size change. Larger buffers cost additional graphics memory, so allocation is explicitly bounded. Only the visible display crop runs the video fragment pass (scissor), while the remaining canvas is cleared. The HUD reports the actual output size and effective gain limited by both atlas density and final buffer resolution.

“Show quality diagnostics” is saved separately. Disabling it removes the map, tint and debug heartbeat without disabling view streaming. A frame-expiry callback remains active independently, so fallback does not depend on the debug HUD. The hardware test includes a one-pixel black/white pattern through the real decoder and compares reduced versus native-sized output contrast.


### Gaze curvature, encoder controls and live resources

Curvature and dense streaming use one filtered fine-gaze source target, independently of desktop eye-mouse aiming. Gaze resolves against an undeformed reference sphere, avoiding feedback from the deformation it drives. During experimental streaming, curvature consumes the focus attached to the currently presented video frame, aligning transport latency with the dense region. Tracking gaps retain the target. Flat geometry stays unchanged. Spherical mode requests fine-eye permission even when the streaming experiment is off. The actual visible crop still uses the headset FOV.

Workspace Settings persists Fast/Balanced/Quality encoder presets, a 0–200 Mbps override (0 means the host's configured default), sharpening 0–1.5 and dense crop fraction 20–65%. Dense percentage applies separately to the visible crop's width and height, not its area. Narrowing it assigns the same 2048×1024 dense tile to fewer source pixels, up to source/output/headset limits. Encoder presets change backend effort while retaining low-latency buffering. Bitrate/preset changes rebuild the normal encoder with an IDR and reconnect the experimental encoder; the client reconfigures MediaCodec when parameter sets change. Sharpening is an optional GPU luminance unsharp filter, bounded by the local neighborhood to limit halos; it defaults off, applies to either stream and never sharpens the HUD. Sampling is clamped within each atlas tile to avoid crossing the tile seam.

Live resources defaults on and is independent of experimental diagnostics. A one-Hz background sampler reports host process CPU/RSS, system available RAM, encoded frames/s and payload Mbps. Host GPU is the busiest per-process DRM engine normalized by engine capacity; unavailable counters show n/a. Headset CPU/PSS, available RAM and graphics memory come from Android/proc statistics; its GPU counter is device-wide where the kernel exposes it, otherwise n/a. CPU 100% means one occupied core. Image FPS counts latched video images; redraw FPS counts compositor swaps, not headset display FPS. GL submit time measures CPU submission plus swap, not a GPU timer. Capture/encode timings apply to successful experimental frames and show n/a in normal mode. Sampling reads bounded process counters without adding desktop captures or encoder instances. The screen overlay and fixed Workspace status display live values, with a saved switch to hide them.

A synthetic hardware-decoded one-pixel pattern verifies detail survives the source-native output path (contrast 255 versus 0 through the reduced output). Separate real-EGL checks verify sharpened edge contrast, unchanged flat areas, restoration at zero strength and resource HUD visibility in normal streaming. These establish the processing path, not a guaranteed subjective improvement through the headset optics.
